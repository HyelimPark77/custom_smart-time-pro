# 마음섬 쉼 알림 · 수동 전송

수동 통합 APK에서 실제 워치의 메시지 표시·진동을 사용자가 확인했다. Java/DEX 컴파일, 서명, 핵심 파일 70개 보존 검사, 브라우저 음성·쉼 알림 검사 및 기존 모델 검사를 통과했다. 검증 범위와 APK 해시는 `analysis/watch-reminder-0.7.0-dev.1-verification.json`에 기록한다.

마음섬 → 쉬어가기 → ‘워치로 쉼 알림 보내기’를 누르면 시험 메시지 한 건을 요청한다. 화면 진입·호흡 시작·건강 기록 조회로 자동 전송하지 않는다.

`WatchReminder`는 기존 `BleConnector.INSTANCE`의 `isAvailable()`을 확인한 뒤 `BleNotification(127, time, ownPackage, title, content)`을 `BleKey.NOTIFICATION`, `BleKeyFlag.UPDATE`, `false, false`로 전송한다. 원본 `MyNotificationListenerService`와 같은 BLE 전송 API이며, 자신의 패키지 알림을 제외하는 Android 알림 수신 경로를 거치지 않는다. 권한 추가나 알림 수신 설정 변경, 전화용 오디오 요청은 하지 않는다.

`sendObject`의 true는 기존 BLE 메시지 큐가 요청을 받아들였다는 의미다. 도착·표시·진동 완료로 표시하지 않는다. 실제 워치의 표시·진동은 별도 확인해야 하며 방해 금지·워치 설정·연결 끊김에 영향을 받을 수 있다. 전송 요청 성공 후 30초 동안 추가 요청을 막는다. 앱 프로세스 재시작 시 이 제한은 초기화된다.

## 예약 알림 초안

매일 한 시각(시·분 단위, 예: 09:10 또는 15:25) 또는 10·15·20·30·60·120분 간격 중 한 방식을 선택하고 저장한다. 끄면 해당 PendingIntent를 취소한다. Android의 기존 SCHEDULE_EXACT_ALARM 선언을 사용하고 `canScheduleExactAlarms`를 확인해 허용이 없으면 저장하지 않는다. 설정 화면으로 이동한 뒤 사용자가 직접 허용하고 다시 저장한다. 자동 허용·권한 우회는 하지 않는다.

AlarmManager의 일회성 `setExactAndAllowWhileIdle`로 다음 예약을 만들며 수신 후 재예약한다. 간격 모드는 저장 시각부터 시작하고 실행이 지연되면 그 실행 시점부터 다음 간격을 센다. 앱을 다시 여는 것만으로 미래의 간격 예약을 뒤로 밀지 않는다. 재부팅·앱 업데이트·시간/시간대 변경 때 저장된 설정으로 재예약한다. 앱 강제 종료 시에는 다시 열어야 한다. 워치 연결이 없으면 결과를 남기고 해당 회차를 건너뛴다. 자동 재연결 및 지난 알림 몰아 보내기는 구현하지 않았다. 절전·연결·OS 상태에 따른 실제 지연과 프로세스 종료 후 동작은 실물 시험 대상이다.

## 변화 알림을 위한 기록 확인

사용자 선택에 따라 먼저 최근 24시간의 심박수·스트레스 기록 중 마지막 8개 값과 측정 시각·인접 기록 간격을 표시한다. 기존 Room DAO의 실제 기록만 읽고 테스트 데이터 메서드는 사용하지 않는다. `Pressure`는 혈압 테이블과 별개의 스트레스 기록이다. 이 화면이 실시간 센서 수집이나 정기 수신 보장을 의미하지 않는다. 기록을 보고 비교 시간·변화량·운동 중 제외·알림 간격을 정하기 전까지 자동 수치 조건 알림은 동작하지 않는다.

음성 입력 설정은 변경하지 않는다. 브라우저 검사는 명시 전송·중복 요청 방지·게임 상태 보존·결과 문자열·6개 간격 선택·시각 예약과 끄기·기록 유무 표시를 확인한다. Java 시각 계산 검사는 당일·다음 날·연도 경계·일광 절약 시간 전환을 확인한다. 설치 APK의 정적 검사와 실제 예약 전송 성공은 구분한다.
