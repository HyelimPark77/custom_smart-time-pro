# 워치 음성으로 마음 날씨 선택

## 사용 흐름

마음섬 → 마음 날씨 → **워치로 마음 말하기** → **워치로 말하기 시작** → 안내 후 10초 말하기 → 인식 문구와 날씨 후보 확인/수정 → **이 마음 날씨로 적용하기** → 마음섬의 **오늘의 마음 남기기**로 저장.

## 마음섬과 같은 화면 구성

- 기존 토끼·별 이미지를 재사용하고 라벤더·민트·분홍 배경, 둥근 카드, 보라색 버튼으로 맞췄다.
- 연결 확인 → 10초 말하기 → 마음 확인 순서를 안내한다. 시작 시 입력 카드, 인식 완료 시 확인 카드로 이동한다.
- 잔잔함은 민트색 잔잔한 수면, 바람은 보라색 공기 흐름 아이콘을 사용한다. 마음섬 웹 화면과 음성 입력 화면에서 같은 형태를 쓴다.
- 입력 시간은 6초에서 10초로 늘렸다. 입력 데이터 길이·남은 시간·인식 응답 제한도 함께 조정했다. 이전의 저장·재실행 성공 시험은 6초 입력 구성에서 진행했으며, 10초 구성의 실물 재시험은 별도로 기록한다.

- 한국어 문장에서 명시적인 마음 날씨 단어를 찾는다. 감정을 추정하거나 진단하지 않는다. 여러 날씨가 섞이면 직접 선택한다.
- 적용만으로 기록하지 않는다. 기존 메모를 보존하고 기존 저장 경로와 보상 규칙을 사용한다. 인식 문구는 화면에서만 확인하며 메모에 자동으로 넣지 않는다.
- 실패하거나 권한을 허용하지 않으면 기존 마음 날씨 직접 선택을 사용할 수 있다.

## 지원 조건과 구현

- 음성 입력 화면은 Android 13 이상, 사용 가능한 기기 내 음성 인식기, 마이크 및 Bluetooth 연결 권한이 필요하다.
- 워치의 건강 데이터용 BLE 연결과 전화용 HFP 연결은 별개다. 이 기능은 전화용 연결이 필요하다.
- 연결된 Diz-SW01 계열 워치가 한 대일 때만 사용한다. Bluetooth 음성 연결 완료를 기다리고 같은 주소의 입력 장치를 지정한다. 실제 녹음 경로가 해당 SCO 장치인지 계속 검사한다.
- 16kHz/mono/PCM16 입력을 메모리에만 수집하고, 기기 내 SpeechRecognizer에 외부 오디오 및 구간 인식 세션으로 전달한다. 온라인 인식기로 자동 전환하지 않는다. 마이크 음성을 파일로 저장하지 않는다.
- 중단·화면 이탈·종료 때 인식기와 오디오를 정리한다. 이 앱이 요청한 통신 경로를 해제하고, 이 세션에서 열었던 워치 음성 오디오를 닫은 뒤 모드를 복원한다.
- 워치의 AI 음성 버튼을 마음섬 실행 버튼으로 바꾸거나 빅스비 인식 결과를 읽는 구현은 아니다.

## 검증 범위

- 별도 시험 앱: S25 Android 16 / Diz-SW01에서 실제 음성 `오늘 마음 흐림` → 텍스트 → 흐림 후보 선택을 확인했다.
- 본 통합 코드: Java/DEX 컴파일 통과. 기존 마음 기록 및 활동 추천 모델 검사 통과. 브라우저에서 자동 저장 방지·메모 보존·잘못된 결과 거부·문자열의 HTML 실행 방지·저장 후 새로고침을 검증했다.
- 별도 확장 APK를 S25에 기존 0.6.0과 함께 설치하고, 본 앱의 마음섬에서 `오늘 마음 흐림` 인식 → 흐림 후보 선택을 실제 화면에서 확인했다. 사용자가 적용·저장했고 씨앗 17개와 흐림 선택 상태를 확인했다. 확장 앱 업데이트 및 완전 종료·재실행 후에도 흐림 기록과 씨앗 17개가 유지됐다. 한 차례의 전체 흐름 검증이며 반복·재연결 안정성 시험은 남아 있다.
- 재실행 때 기존 제조사 자동 앱 업데이트 안내가 새 식별자에 표시되는 문제를 발견했다. 기존 커스텀 앱의 `checkAppVersion` 예외에 확장 식별자만 추가했다. 워치 펌웨어 업데이트는 변경하지 않았다. classes19.dex 7,311개 클래스를 정규화된 Smali 텍스트로 비교해 해당 메서드 외에는 동일함을 확인했다. 비교 도구는 `tests/VerifyVoiceCore.java`다.
- 수정 APK의 재실행에서 제조사 자동 앱 업데이트 안내가 나타나지 않았고 마음섬에 정상 진입했다. 기존 설정의 수동 앱 업데이트 메뉴는 별도 정리 대상이다. 설치용 APK의 해시·정적 검사·실물 검증 범위는 `analysis/watch-voice-0.7.0-dev.1-verification.json`에 기록했다.

## 마이크 장치 준비 실패 후속 수정

**최종 사용자 선택:** 사용자가 10초 수정본의 실제 음성 인식 성공을 확인한 뒤 사용성상 6초를 선호해 다시 변경했다. 현재 입력은 6초이며 연결·입력 경로 확인·종료·인식기 설정은 성공 버전 그대로다. 아래 10초 변경 및 실패 조사 내용은 진행 이력이다.

**최신 상태:** 연결 처리 변경 없이 복원 버전으로 다시 시험한 뒤 사용자가 음성 인식 성공을 보고했다. 사용자의 요청에 따라 이 성공 버전의 연결 준비·입력 경로 확인·종료·인식기 설정은 유지하고 녹음 길이, 버퍼 총량, 카운트다운, 입력 길이에 따른 RMS 분모와 안내만 10초로 변경했다. 인식 응답 제한도 복원 버전의 20초를 유지한다. 10초 수정본의 실물 인식 성공은 별도 확인 대상이다. 성공/실패가 바뀐 정확한 원인은 아직 확정하지 않았다.

**현재 비교 시험 빌드:** 사용자 요청에 따라 성공 이력이 있는 `42798cbc`의 `capture()` 전체를 동일하게 복원했다. 연결 준비·녹음·경로 확인·종료 처리와 녹음 6초를 포함하며, 인식 응답 제한도 당시의 20초로 복원했다. 마음섬 UI는 유지하고 안내는 6초로 맞췄다. 10초 요청은 취소한 것이 아니라 성공 기준 재확인 후 시간만 바꾸어 재검증하기 위해 보류한 것이다. 아래 연결 수정들은 실패 원인 조사 이력이며 현재 빌드에는 적용하지 않는다. 복원 빌드의 실물 성공은 아직 확인되지 않았다.

복원 빌드에서도 사용자가 ‘출력 연결은 있지만 마이크 입력 장치가 없음’을 보고했다. 최신 기록에는 확장 앱과 이전 시험 앱 양쪽의 실패가 있다. HFP는 연결 상태지만 별도 시험 앱의 마지막 시도에서 SCO `AudioOn` 이후 약 0.2초에 연결 종료 이벤트가 먼저 발생했고, 앱의 종료 처리는 그 뒤였다. 어느 쪽의 종료 요청인지 아직 확정하지 않았다. 추가 APK 변경 전에 현재 기본 AI 음성→빅스비 경로와 비교한다.

전화용 HFP가 연결된 상태에서 ‘출력 연결은 있지만 마이크 입력 장치가 없음’ 오류가 보고됐다. S25 오디오 기록에서 SCO 출력·입력이 나타났다가 경로 선택 요청 직후 사라지는 것을 확인했다. 설정 순서 경쟁 가능성이 있어 아래를 수정했다. 실제 복구 성공 여부는 재시험 대상이다.

- HFP 음성 통로에서 워치 경로를 얻은 뒤 통화 모드 설정과 이 앱의 경로 요청을 연속 실행한다. 통화 모드를 먼저 설정한 중간 수정은 아래 실물 실패 기록에 따라 철회했다.
- 전역 경로가 이미 같은 워치여도 이 앱의 `setCommunicationDevice` 요청은 반드시 등록한다. 전역 선택만 보고 요청을 생략했던 첫 수정은 철회했다.
- 출력·입력 장치가 게시될 때까지 제한된 시간 동안 기다린다. 실제 녹음 경로가 해당 워치인지 확인하는 검사는 유지한다.
- 종료 시 휴대폰 수화기를 명시적으로 다시 지정하는 대신 이 앱의 경로 요청만 해제한다. 다른 앱을 강제 종료하거나 페어링을 삭제하는 동작은 추가하지 않았다.

첫 수정 뒤에도 실패했다. 시스템에 남아 있던 별도 시험 앱의 수화기 경로 요청을 사용자 승인으로 제거했지만 실패가 계속돼 단독 원인으로 보지 않는다. 이어진 기록에서 확장 앱 자체의 통신 요청 목록이 비어 있었고 모드 소유권 변경 시 SCO가 닫혔다. 전역 선택과 이 앱의 통신 요청 등록을 구분하도록 보완했으며 실물 재시험이 필요하다.

앱의 경로 요청을 명시적으로 등록한 시험에서도 실패했다. 워치 입력을 잠깐 확인한 뒤 약 0.6초 안에 장치가 사라져 중단됐다. 기록에는 경로 요청 등록 이전의 `setNewModeOwner` 및 `handleDeviceConnection`에서 `stopBluetoothSco`가 호출된 흔적이 있다. 통화 모드와 경로 요청 사이 대기를 없애는 후속 빌드를 준비했다. 종료 요청 경쟁이라는 가설을 검증하는 단계이며 10초 녹음 성공으로 기록하지 않는다.

모드 설정 순서를 바꾼 시험도 실패했다. 최신 빌드는 사용 가능한 워치 통신 장치가 있으면 HFP `startVoiceRecognition`을 먼저 호출하지 않고 `setCommunicationDevice`로 직접 요청한다. 워치 통신 장치가 아직 없는 경우에만 HFP 개방을 준비 경로로 사용한다. 이는 외부 음성 세션과 앱 세션 사이 전환 경쟁을 줄이기 위한 수정이며 실물 검증 대기 상태다. 참고: https://developer.android.com/develop/connectivity/bluetooth/ble-audio/audio-manager

## 별도 확장 앱 빌드

기존 문서에 따라 원본 작업 자료를 복원하고 SDK 35 및 build-tools 35.0.0을 준비한다.

```powershell
$env:ANDROID_HOME = 'C:/Users/your-user/AppData/Local/Android/Sdk'
./scripts/Build.ps1 -IdentityProfile profiles/diz-sw01-watch-integration.json
```

이 프로필은 `디즈 워치 마음섬 확장`, `com.diz.sw01.watch.integration`, `0.7.0-dev.1`로 별도 설치한다. 앱 데이터와 권한도 별도이며 기존 마음섬 기록을 자동으로 가져오지 않는다. 두 앱이 같은 워치에 동시에 연결하면 충돌할 수 있어 실제 시험 때는 한 앱에서만 연결한다. 원본 앱을 삭제하지 않는다.

## UI 회귀 검사

```powershell
$env:PLAYWRIGHT_MODULE = 'path/to/playwright'
$env:BROWSER_EXECUTABLE = 'path/to/browser.exe'
node tests/watch-voice-ui.cjs
```
